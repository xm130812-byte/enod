# 一次失败的重构

> 这是剪藏功能的示例文档：`source` 里的信息来自网页，阅读时顶部会显示来源。

上周我们花三天重构了索引层，上线后搜索变慢了 4 倍。这篇记录发生了什么。

## 我们做了什么

把「读取 + 解析 + 写库」从一个大函数拆成三个模块，加了一层缓存。代码确实更漂亮了。

## 哪里错了

- 缓存键用了 `mtime`，但同步盘会把 `mtime` 改来改去；
- 拆模块时把批量事务改成了逐条提交；
- 没有基准测试，只有"感觉快了"。

## 数字

| 版本 | 3000 篇索引耗时 | P95 搜索 |
|---|---|---|
| 重构前 | 21s | 18ms |
| 重构后 | 96s | 74ms |

## 教训

优化之前先测量。**"结构更清晰"不是性能证据。**
