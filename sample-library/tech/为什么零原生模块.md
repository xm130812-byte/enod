# 为什么零原生模块

一个本地优先的 Markdown 阅读器，为什么要在依赖上如此克制？

## 一句话答案

因为**安装体验就是产品体验的一部分**。用户双击安装包之前，不应该先装一个 C++ 编译器。

## 被替换掉的东西

| 常见选择 | 本项目的替代 | 代价 |
|---|---|---|
| `better-sqlite3` | `node:sqlite` | API 仍标注 experimental |
| `nodejieba` | `Intl.Segmenter('zh')` | 分词精度略低 |
| `sharp` | 不做缩略图 | 大图首屏略慢 |
| `fsevents` / `chokidar` | `fs.watch({ recursive: true })` | 事件有 ~100ms 合并延迟 |

铁律：不引入任何需要编译的原生模块。一旦破例，Windows 要 VS Build Tools，macOS 要 Xcode CLT，CI 要维护多套构建机。

## 数据库连接

```ts
import { DatabaseSync } from 'node:sqlite';

const db = new DatabaseSync('index.db');
db.exec('PRAGMA journal_mode = WAL');
db.exec(`
  CREATE VIRTUAL TABLE IF NOT EXISTS docs_fts
  USING fts5(doc_id UNINDEXED, body_tokens, tokenize = 'unicode61');
`);
```

零安装，零编译。代价是它还在 experimental，所以整个项目只在 `db.ts` 里 import 它——需要时换回 `better-sqlite3` 只改一个文件。

## 中文分词

`Intl.Segmenter` 是 V8 内置的 ICU 能力：

```ts
const seg = new Intl.Segmenter('zh', { granularity: 'word' });
[...seg.segment('决定战争胜负的是人不是物')].map((s) => s.segment);
// ['决定', '战争', '胜负', '的', '是', '人', '不是', '物']
```

它不完美，但对"读自己硬盘里的文章"这件事，够用了。

## 代价公式

$$
\text{维护成本} = \text{平台数} \times \text{工具链版本} \times \text{故障概率}
$$

把"平台数"与"工具链版本"都压到 1，剩下的复杂度才留给真正的产品问题。

## 结论

克制不是目的，**把复杂度花在用户能感知的地方**才是。批注能不能正确落回原文，比用不用 jieba 重要得多。
