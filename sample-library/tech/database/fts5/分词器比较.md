# 分词器比较

中文检索绕不开一个问题：把一句话切成什么单位。

## 三种方案

| 方案 | 依赖 | 召回 | 成本 |
|---|---|---|---|
| `unicode61` 原样 | SQLite 内置 | 只按空格切，中文整段一个 token | 0 |
| bigram（二元组） | 纯 JS | 高，但索引膨胀约 35% | 低 |
| `Intl.Segmenter('zh')` | V8/ICU 内置 | 接近词级 | 0，且跨平台 |

## 我们用哪种

主索引用 `Intl.Segmenter`，另存一列 bigram 兜底。这样「中文检索」既能在分词命中时精确排序，也能在分词器切错时靠二元组召回。

```ts
const seg = new Intl.Segmenter('zh', { granularity: 'word' });
const tokens = [...seg.segment(text)]
  .filter((s) => s.isWordLike)
  .map((s) => s.segment.toLowerCase());
```

## 一个反例

「南京市长江大桥」如果切成「南京 / 市长 / 江大桥」，搜索「长江大桥」就会漏。bigram 能把「长江」「江大」「大桥」都留下，代价是噪音变大。

索引结构与 FTS5 的用法见 [[SQLite FTS5 中文检索]]，存储层的取舍见 [[SQLite 的 WAL 模式]]。
